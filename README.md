# URP-CustomPostProcessing

Experimental playground of learning URP 

# URP vs BIRP
When the CPU needs data generated by the GPU (like a screenshot, a compute shader output, or an occlusion query), the pipeline must synchronize.
- The Bad/Synchronous Way (BiRP): Historically, developers used `Texture2D.ReadPixels()`. This forces a hard pipeline stall. The CPU stops everything, sends the command, and literally idles until the GPU finishes rendering the frame & copies the memory back to RAM. Such synchronisation slows down the performance of a 3D graphics application.
- The Modern/Asynchronous Way (URP): Unity introduced the `AsyncGPUReadback` API. Instead of stalling the main thread, `AsyncGPUReadback.Request()` inserts a request into the GPU's command buffer. The CPU keeps running subsequent frames. A few frames later (typically 1 - 3 frames delay), the CPU checks if the data is ready and processes it.

Use Case: Generating procedural planet terrain heights via compute shaders and reading them back to generate collision meshes on the CPU.

### Multi-Pass Rendering Dependencies 
When 1 rendering pass relies on the output of a previous pass, the GPU must finish writing the first resource before reading it.
- Built-in Pipeline (BiRP): Unity handled most of this automatically in a black-box system. If you wanted to inject custom dependencies (like blurring the screen before rendering a UI menu), you used CommandBuffer and attached it to specific injection points using `Camera.AddCommandBuffer(CameraEvent.AfterImageEffects, cmd)`
- Universal Render Pipeline (URP): URP makes this much more explicit & flexible. Instead of attaching loose command buffers to a camera, you create a `ScriptableRendererFeature` containing a `ScriptableRenderPass`. You use the ConfigureTarget() and ConfigureInput() methods to tell the pipeline exactly which textures you are reading and writing.
  - Note: In the newest versions of URP (Unity 6 / URP 17+), Unity uses the Render Graph API. You declare your resource dependencies up front -> the Render Graph automatically calculates the exact barriers and sync points required so Pass B doesn't execute until Pass A is 100% finished.
